# v0.1 two-host release benchmark — `0ad4ccf`

This preregistered run corrected the first two-host harness by capping GSO/GRO
aggregation at the 1,500-byte MTU inside each ephemeral sender container. It
transferred one authenticated 16 MiB object between the x86_64 `spider` sender
and an ARM64 Raspberry Pi receiver. All 72 randomized transfers completed and
passed end-to-end SHA-256 verification.

| Criterion | Complete blocks | Estimate | One-sided 95% bound | Threshold | Decision |
| --- | ---: | ---: | ---: | ---: | --- |
| Clean: UDP time / best TCP time | 12 | 1.0670 | upper 1.0900 | <= 1.05 | Fail |
| 1% loss: best TCP time / UDP time | 12 | 2.1740 | lower 1.7876 | >= 1.25 | Pass |

The combined release claim is therefore **not established** at this revision.
The lossy advantage remains decisive, while clean-path parity does not pass.

Spider exceeded the normalized-load ceiling after five complete clean blocks.
The initial process stopped at its predeclared five-minute idle timeout. Strict
continuation reused the original run ID and randomized schedule, verified the
same endpoint artifacts and machine IDs, and skipped only complete
three-treatment blocks. An interrupted continuation left a run-scoped native
receiver bound to block 5's port; no result was written for that block. After
adding exact-run receiver cleanup, continuation 3 reran block 5 in its original
order and completed the matrix. The numbered continuation records are retained.

Block-level diagnosis showed UDP clean times tightly grouped around 1.588--1.593
seconds. Fast single-stream TCP blocks took roughly 1.426--1.468 seconds. TCP
hashes bytes incrementally as it receives them, while this UDP revision performs
a second full-file SHA-256 pass only after all chunks and repairs arrive. A Pi
loopback profile exceeded 300 Mbit/s for the authenticated UDP path, ruling out
the receiver's packet processing and storage write rate as the 100 Mbit/s cap.
Incremental hashing of each currently contiguous object prefix is the next
implementation hypothesis; this result is not filtered or reinterpreted.
