# v0.1 two-host release benchmark — `911775b`

This preregistered run transferred one authenticated 16 MiB object between two
independent Linux machines: the x86_64 `spider` sender and an ARM64 Raspberry Pi
receiver. The Pi was reached through `spider` as an SSH jump host; the transfer
itself used the private Ethernet path directly. All 72 randomized transfers
completed and passed end-to-end SHA-256 verification.

| Criterion | Complete blocks | Estimate | One-sided 95% bound | Threshold | Decision |
| --- | ---: | ---: | ---: | ---: | --- |
| Clean: UDP time / best TCP time | 12 | 1.0443 | upper 1.0725 | <= 1.05 | Fail |
| 1% loss: best TCP time / UDP time | 12 | 2.5611 | lower 2.1636 | >= 1.25 | Pass |

The combined release claim is therefore **not established** at this revision.
The clean point estimate is within the parity threshold, but the preregistered
confidence bound is not. The failed observation is retained rather than filtered
or replaced.

UDP clean-path times were unusually stable at 1.589--1.594 seconds. Single-stream
TCP alternated between roughly 1.44--1.47 and 1.88--2.04 seconds, while four-lane
TCP remained around 1.58--1.66 seconds. In the faster single-stream TCP blocks,
UDP was 8--11% slower. The leading implementation hypothesis is per-datagram
`thread::sleep` overshoot in the sender pacer: at 100 Mbit/s it requests a sleep
about every 96 microseconds, magnifying scheduler overhead. This hypothesis must
be fixed and tested in a newly preregistered run; it is not a basis for changing
this decision.
